# CLAUDE.md — MyTodos

## Project overview
MyTodos is a minimal, single-user todo app: create, edit, complete/uncomplete, delete, and list todos, with an optional due date.
There is no authentication and no database. Data lives in memory and resets when the backend restarts. This is intentional; do not "fix" it.

The full spec is in `MyTodos-PRD.md`. When in doubt about scope, follow the PRD.

## Tech stack
- **Backend:** ASP.NET Core Web API on **.NET 8 (LTS)**, C#, controllers (not minimal APIs)
- **Frontend:** React + **TypeScript** (`.tsx`), built with Vite
- **HTTP client:** **axios**
- **Tests:** **xUnit** for the backend only. No frontend tests in v1.
- **Storage:** in-memory, via a singleton service

## Commands
Backend (from `MyTodos.Api/`):
- Run: `dotnet run` (serves on `https://localhost:5001`; set this in `Properties/launchSettings.json`)
- Build: `dotnet build`
- Test (from repo root): `dotnet test`

Frontend (from `mytodos-frontend/`):
- Install: `npm install`
- Dev server: `npm run dev` (serves on `http://localhost:5173`)
- Type check + build: `npm run build`
- Lint: `npm run lint`

## Data model
| Field | C# type | TS type | Notes |
|---|---|---|---|
| `id` | `Guid` | `string` | Generated by the backend with `Guid.NewGuid()` |
| `title` | `string` | `string` | Required, must not be empty or whitespace. Trim before saving. |
| `dueDate` | `DateOnly?` | `string \| null` | Optional, serialized as `yyyy-MM-dd` |
| `isComplete` | `bool` | `boolean` | Defaults to `false` |
| `createdAt` | `DateTime` (UTC) | `string` | Set by the backend on create, never changed by the client |

JSON uses camelCase (the ASP.NET Core default). Keep `types/todo.ts` in sync with `Models/Todo.cs` whenever either changes.

## API contract
Base path: `/api/todos`

| Method | Route | Body | Success | Errors |
|---|---|---|---|---|
| GET | `/api/todos` | — | 200, array of todos (optional `?status=pending\|completed\|all`, default `all`) | 400 if `status` is invalid |
| GET | `/api/todos/{id}` | — | 200, todo | 404 |
| POST | `/api/todos` | `{ title, dueDate? }` | 201 + `Location` header, created todo | 400 if title empty |
| PUT | `/api/todos/{id}` | `{ title, dueDate?, isComplete }` | 200, updated todo | 400, 404 |
| DELETE | `/api/todos/{id}` | — | 204 | 404 |

Clients never send `id` or `createdAt` in request bodies.

## Backend conventions
- Controllers stay thin: validate input, call `ITodoService`, map results to HTTP responses. Business logic belongs in `TodoService`.
- `TodoService` is registered with `AddSingleton<ITodoService, TodoService>()`. Because a singleton is shared across concurrent requests, guard the collection with a `lock` (or use `ConcurrentDictionary<Guid, Todo>`).
- Use data annotations (`[Required]`, etc.) on request DTOs plus an explicit whitespace check on `title`. Return `ValidationProblem`/`BadRequest` for invalid input.
- Use async signatures on the service interface (`Task<...>`) so a real database can be added later without changing callers.
- CORS: a named policy in `Program.cs` allowing origin `http://localhost:5173`, any header, any method.
- Enable nullable reference types and treat warnings seriously.

## Frontend conventions
- Function components and hooks only. No class components.
- All network calls go through `services/todoApi.ts`. Components never import axios directly.
- Create one axios instance with `baseURL` read from `import.meta.env.VITE_API_BASE_URL` (default `https://localhost:5001/api`). Define it in `.env.development`.
- `App.tsx` owns the todo list state. After each create/update/delete, update state from the API response so the UI reflects the server immediately.
- Delete uses `window.confirm(...)` before calling the API, per the PRD.
- Completed todos render with strikethrough and muted color.
- Show a simple error message when an API call fails; don't let a failed call crash the app.
- No `any`. Type every prop, API response, and state value.
- Plain CSS in `index.css` (or co-located `.css` files). Don't add a UI or styling library without asking.

## Testing
- Backend: xUnit tests in `MyTodos.Api.Tests/`. Cover `TodoService` CRUD, title validation, `status` filtering, and 404 paths in the controller.
- Add or update tests whenever backend behavior changes, and run `dotnet test` before finishing.
- Frontend: no tests in v1. Verify with `npm run build` (type check) and `npm run lint`.

## Out of scope for v1 — do not add
Authentication or user accounts, databases or file persistence, priorities/tags/categories/subtasks, reminders or notifications, sorting, pagination, offline support. (Filtering `GET /api/todos` by completion status via `?status=` is implemented — see API contract; other filtering is still out of scope.) If a task seems to need one of these, stop and ask first.

## How to work in this repo
- Implement changes directly; no need to wait for plan approval.
- After finishing, give a short summary: what changed, which files, and anything I should know or verify.
- Before declaring a task done: backend builds and `dotnet test` passes; frontend `npm run build` and `npm run lint` pass.
- Keep changes focused on the task. Don't refactor unrelated code or add new dependencies without mentioning it in the summary.
- Ask before anything destructive or outside the repo (deleting files you didn't create, changing global config, installing global tools).
